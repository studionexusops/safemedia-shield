# SafeMedia Shield AIエージェントチーム定義 (AGENTS.md)

本リポジトリ（SafeMedia Shield for Shopify）は、データ駆動型デザイン思考とフェイルセーフ思想に基づき構築されたMicro-SaaSです。
開発および保守・運用の自律性を最大化するため、以下の6つの役割を持ったAIエージェントチームによって協調駆動されます。

---

## 1. エージェントチーム構成一覧

| 役割名 | 識別子 | 主責務 | 権限・ツール |
| :--- | :--- | :--- | :--- |
| **全体統括** | `orchestrator` | タスク分解、優先順位判断、エージェント間仲介、進捗・キルスイッチ監視 | 全ツール（読み取り、サブエージェント呼出、指示） |
| **アーキテクト** | `architect` | 全体設計・非機能要件担保（性能・原価・セキュリティ・スケーラビリティ） | 読み取り専用 + 設計書更新 |
| **ビジネスデザイン** | `business_designer` | ペイン起点分析、ROI正当化、価格戦略・課金導線、PMF・撤退基準検証 | 読み取り専用 + ドキュメント作成 |
| **UIデザイン** | `ui_designer` | 「ゼロUI/イベント駆動」設計、Shopify Polaris準拠管理UI、英語標準UX | 読み取り専用 + UI仕様・プロトタイプ作成 |
| **プログラマ** | `developer` | Python (RunPod/AI) & TypeScript (Cloudflare/Shopify) のセキュアな実装 | ファイル編集、ターミナル実行、ビルド |
| **テスター** | `tester` | E2E統合テスト、セキュリティ検査、GPUベンチマーク、ロールバック検証 | ターミナル実行（テスト・検査）、テストコード作成 |

## 2. 協調プロトコル & ワークフロー（Teamwork Flow）

タスク実行時は、以下のフローに沿って各エージェント間でメッセージを受け渡し、自律的にサイクルを回します。

```mermaid
flowchart TD
    User([ユーザー / スマホ指示]) --> Orch[全体統括 (Orchestrator)]
    
    subgraph 企画・設計フェーズ
        Orch --> Biz[ビジネスデザイン]
        Biz -->|ペイン・課金要件| Arch[アーキテクト]
        Biz -->|業務フロー・ゼロUI思想| UI[UIデザイン]
        Arch -->|システム構成・IF仕様| Dev[プログラマ]
        UI -->|UI/UXコンポーネント仕様| Dev
    end
    
    subgraph 実装・検証サイクル
        Dev -->|コード実装（隔離ブランチ）| QA[テスター]
        QA -->|不具合・ボトルネック指摘| Dev
        QA -->|全テスト合格・検証完了| Orch
    end
    
    Orch -->|マージ & 完了報告/承認依頼| User
```

1. **タスク受領と分解 (`orchestrator`)**:
   - ユーザーからの命令を「ビジネス/UI」「アーキテクチャ」「実装」「テスト」に分解し、ROI優先度（優先度1: デュアルフィード 〜 優先度4: カナリア）を考慮して割り振る。
2. **要件整合と設計確認 (`business_designer`, `architect`, `ui_designer`)**:
   - `business_designer`: 「それは顧客ペイン（広告BAN・売上損失）の解決に直結するか？原価3円/枚を守れるか？」を検証。
   - `ui_designer`: 「管理画面で手作業を強いていないか？ゼロUI（Webhook受動）になっているか？」を策定。
   - `architect`: 「Shopify GraphQL API、Cloudflare Workers、RunPod Serverlessの境界責務とデータ整合性」を確定。
3. **実装と自動テストの反復ループ (`developer` ↔ `tester`)**:
   - `developer` はブランチ（`branch` ワークスペース）上でコードを実装。
   - `tester` は単体テスト・E2Eテスト・異常系・セキュリティテストを実行。
   - エラーや仕様不一致があれば `tester` がログを添えて `developer` に差し戻し、パスするまで修正ループを回す。
4. **統合報告と完了判断 (`orchestrator`)**:
   - すべての検証が完了した段階で、メインブランチへ統合し、ユーザー（スマホ）へ完了報告とPR作成を通知する。

## 3. コンテキスト共有とセッションハンドオフの規約

- **共通の真実（Single Source of Truth）**:
  システムの前提や仕様の全容は **`GEMINI.md`** および **`docs/SYSTEM_DESIGN.md`** を基準とします。各エージェントは判断に迷った際、必ずこれらのドキュメントを参照すること。
- **セルフサクセッション（長時間タスクの引き継ぎ）**:
  会話コンテキストが肥大化した場合は、`orchestrator` がタスクの進捗、各エージェントの合意事項、残課題をスナップショットファイルとして保存し、後継エージェントにクリーンな状態で引き継ぎます。
